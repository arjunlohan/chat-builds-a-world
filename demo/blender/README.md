# Demo B-roll (prerendered)

These are Blender concept clips built from procedural scripts Codex wrote for the
demo video. They are prerendered, are **not generated by the running product**, and
are not used by the server or world. Disclose them in the video description and
write-up; no on-screen caption is used. They are separate from the live demo.

All meshes, materials, lighting and motion are generated in code. There are no
downloaded models, textures, HDRIs, fonts, logos or audio.

| Name | Action | Duration | Full / preview frames |
| --- | --- | ---: | ---: |
| `dog-carrot` | A rounded dog pursues a bouncing carrot | 7 s | 210 / 105 |
| `worm-takeover` | A worm enters, grows across the screen, wiggles, shrinks and leaves | 7 s | 210 / 105 |
| `cheer-burst` | Three citizen-like creatures hop beneath balloons and confetti | 6 s | 180 / 90 |

## Render

Install Blender 5.2.3 LTS with EEVEE and put `blender` on PATH. No Python packages,
external encoder, API key or running product server is required. From the repo root:

```sh
pnpm demo:render dog-carrot --preview
pnpm demo:render worm-takeover --preview
pnpm demo:render cheer-burst --preview

pnpm demo:render dog-carrot
pnpm demo:render worm-takeover
pnpm demo:render cheer-burst
```

Omit the name to render all three sequentially. To select another Blender binary:

```sh
BLENDER_BIN=/Applications/Blender.app/Contents/MacOS/Blender pnpm demo:render dog-carrot
pnpm demo:render --help
```

The driver runs `blender -b --factory-startup --python-exit-code 1 -P <script>` and
passes the output path after `--`. It never starts the server or invokes a model.
`pnpm check` does not import these scripts or require Blender.

## Outputs and compositing

Full renders are 1920x1080 at 30 fps with a transparent background, EEVEE, 16 render
samples. Previews are 960x540, every other animation frame, at 15 fps with eight
samples. Preview duration is unchanged. Lower preview sampling is for framing and
motion checks; review the full render before recording/editing the final video.

```text
demo/renders/<name>/
  frames/frame_0001.png ...       # full RGBA sequence
  <name>.mov                     # QuickTime PNG, RGBA, 30 fps
  render.json                    # dimensions, count, timing and codec
  preview/
    frames/frame_0001.png ...
    <name>-preview.mov           # RGBA, 15 fps
    render.json
```

Blender's sequencer encodes the already-rendered PNGs into the movie; it does not
render the 3D scene a second time. QuickTime PNG is lossless and carries alpha.
It is an editing/compositing intermediate, rather than a small delivery file.
The [Blender video-format documentation](https://docs.blender.org/manual/en/5.0/files/media/video_formats.html)
describes the supported codecs.

Import the `.mov` as a media source in OBS or an alpha-capable editor. Composite it
over another source; a black viewer background alone does not indicate lost alpha.
The PNG sequence is also available if an editor needs explicit straight-alpha
interpretation. There is no audio. Worm entry/exit and rising balloons deliberately
cross the frame boundary. Each rerender replaces that clip's generated sequence
and movie; previews do not overwrite full renders.

The scripts use low-detail geometry, bounded object counts and EEVEE without ray
tracing, targeting under four minutes per full clip on the M1 Pro.

The first and last rendered frames must have zero visible alpha; coverage is recorded
in `render.json`, and any nonzero alpha fails the render before movie encoding.

`demo/renders/` and Python bytecode are ignored. Commit scripts and documentation,
not generated media or `.blend` files.
